2  Binary G

In this chapter, we outline the complete workflow for an FDID analysis, which includes preparing the dataset, performing the estimation, and plotting the results.

library(fdid)
data(fdid)

2.1 Data preparation

Before calling fdid_prepare(), make sure

  • each unit has a unique identifier across time;
  • the baseline factor \(G\) is coded as a 0/1 variable. To match the current implementation (binary \(G\)), we define
    • \(G=1\) for counties above the median social-capital measure;
    • \(G=0\) for counties below the median.
mortality$uniqueid <- paste(as.character(mortality$provid), as.character(mortality$countyid), sep = "-")
mortality$G <- ifelse(mortality$pczupu >= median(mortality$pczupu, na.rm = TRUE), 1, 0)

Next, define the key input parameters (event window, reference period, variable names):

tr_period <- 1958:1961
ref_period <- 1957
treat <- "G"
Y <- "mortality"
time <- "year"
unit <- "uniqueid"
covar <- c("avggrain", "nograin", "urban", "dis_bj", "dis_pc",
           "rice", "minority", "edu", "lnpop")

Finally, the user can use fdid_prepare() to reshape long-format panel data into a wide-format dataset and to construct the ingredients needed by fdid(). It also averages time-varying covariates and standardizes naming so downstream steps are consistent.

prepared_d <- fdid_prepare(
  data = mortality,
  Y_label = Y,
  X_labels = covar,
  G_label = treat,
  unit_label = unit,
  time_label = time
)
head(prepared_d)

For DML workflows, fdid_prepare() can also expand the averaged covariates into polynomial or B-spline basis functions and optional pairwise interactions. This is useful when the raw covariate set is low-dimensional but the nuisance models need more flexibility.

prepared_d_hd <- fdid_prepare(
  data = mortality,
  Y_label = Y,
  X_labels = covar,
  G_label = treat,
  unit_label = unit,
  time_label = time,
  basis_type = "polynomial",
  poly_degree = 2,
  include_interactions = TRUE
)

data.frame(
  raw_covariates = length(covar),
  expanded_covariates = length(grep("^x[0-9]+$", names(prepared_d_hd)))
)

Currently, the package accepts only long-format data; if the data are already in wide format, the user must convert them to long format first.

2.1.1 Clustering if needed

Since the estimation program operates on the wide format and each row represents one unit, the robust standard errors we’re using are analogous to clustering at the unit level. However, if needed, the user can choose a different and higher level to cluster by passing the cluster variable (e.g. provid) to fdid_prepare(). Then fdid(..., vartype="robust") will report robust standard errors clustered at the higher level.

prepared_d_cl_prov <- fdid_prepare(
  data = mortality,
  Y_label = Y,
  X_labels = covar,
  G_label = treat,
  unit_label = unit,
  time_label = time,
  cluster_label = "provid"
)

2.2 FDID: A quick review

fdid() performs factorial difference-in-differences (FDID) estimation using cross-sectional estimation methods based on first differences. It converts the \((Y_{i,t}, G_i, X_i)\) into a cross-sectional form \((\Delta Y_i, G_i, X_i)\) by comparing each period (or average of a time window) to a reference period.

fdid() reports both aggregate and dynamic estimates with different definition of \(Y_{i,*}\) in \(\Delta Y_i=Y_{i,*}-Y_{i,\text{ref}}\):

  • Aggregate estimates:
    • Pre-event average effect for all pre-event periods excluding the reference period: \(Y_{i,*}=\bar Y_{i,\text{pre}}\) where \(\bar Y_{i,\text{pre}}\) is the average of \(Y_{i,t}\) across all pre-event periods except the reference period.
    • Event-period average effect for all event periods: \(Y_{i,*}=\bar Y_{i,\text{event}}\) where \(\bar Y_{i,\text{event}}\) is the average of \(Y_{i,t}\) across all event periods.
    • Post-event average effect for all post-event periods: \(Y_{i,*}=\bar Y_{i,\text{post}}\) where \(\bar Y_{i,\text{post}}\) is the average of \(Y_{i,t}\) across all post-event periods.
  • Dynamic Estimates:
    • Dynamic period-by-period estimates relative to the reference: \(Y_{i,*}=Y_{i,t}\) for all \(t\).

How periods are defined: tr_period defines the event window. Every period before it is “pre”, every period after it is “post”. The reference period is separately set by ref_period and does not have to be the last pre-event period. If it’s set in event or post-event window, the corresponding window average effect will also exclude the reference period when calculating the average.

Carryout effect: Because we cannot rule out carryover effects, all periods during or after the event should be considered treated or exposed. Therefore, setting a post-event period as the reference period is not recommended, even though we report separate estimates for the event and post-event periods.

Compared with the TWFE model, our approach

  • forces each period-by-period estimation to use a balanced two-period comparison;
  • makes it easy to plug in selection-on-observables tools (stratification, balancing, matching, IPW, AIPW, outcome modeling, double machine learning, etc.).

The reason why OLS is problematic here is the same as the issue with running a two-way fixed effects (TWFE) model using long-format data such as the violation of the no anticipation assumption.

2.3 Estimation

Use method to choose an estimator:

Method \(G\) type Main estimand
"did" binary or continuous no-covariate DID slope/contrast
"ols1" binary or continuous OLS with additive covariate adjustment
"ols2" binary or continuous OLS with \(G \times X\) interactions
"ebal" binary entropy-balanced contrast
"ipw" binary IPW contrast via generalized random forests
"aipw" binary AIPW contrast via generalized random forests
"kernel" continuous local-linear level and derivative curves
"dml_plr" continuous scalar partially linear DML slope
"dml_flex" continuous flexible DML level curve \(\theta(g)\) and derivative curve \(\theta'(g)\)
"dml_incremental" continuous scalar observed-population average derivative
"dml_binary" binary cross-fitted binary-G DML contrast

Default is ols1.

For fitted continuous-\(G\) curve objects, use fdid_contrast() to report level comparisons such as \(\theta(g_1)-\theta(g_0)\) and fdid_derivative() to report fixed-\(g\) derivative values such as \(\theta'(g_0)\).

The DML methods use learner = "linear" by default for lightweight, reproducible runs. The rendered DML examples in this tutorial use learner = "grf" to show the flexible nuisance-learning path more clearly. Other optional learners include learner = "glmnet"/"lasso", "ridge", "elasticnet", "ranger"/"rf", "gam", "nnet", and "xgboost"/"boosting" when the corresponding backend package is installed.

2.3.1 Difference-in-Differences

By setting method = 'did', the estimated model is the no-covariate specification: \[ \Delta Y_i=\beta_0+\beta_G G_i+\varepsilon_i \] Here, \(\beta_G\) is a cross-sectional analogue of the canonical \(2\times2\) DID estimand.

  tr_period = tr_period,
  ref_period = ref_period,

2.3.3 OLS with interactions

By setting method = "ols2", the estimated model corresponds to the \(OLS_*\) specification: \[ \Delta Y_i=\beta_0+\beta_GG_i+\beta_X'\mathbf{X}_i+\beta'_{GX}G_i\mathbf{X}_i+\varepsilon_i \]

fdid() automatically centers covariates before estimation. With centered \(X_i\), the coefficient on \(G_i\) can be interpreted as consistent estimator for marginal estimand \(\tau_{\text{DID-X}}\) discussed in Xu, Zhao, and Ding (2026). The standard error for ols2 with target.pop = "all" (the default) includes the Lin (2013) super-population correction \(\hat{\gamma}'\hat{\Sigma}_X\hat{\gamma}/n\), where \(\hat{\gamma}\) are the estimated interaction coefficients and \(\hat{\Sigma}_X\) is the sample covariance of the covariates.

2.3.7 DML binary

method = "dml_binary" keeps the binary-\(G\) target but replaces hand-specified outcome and propensity models with cross-fitted nuisance learning. It is best read as the DML version of an AIPW-style binary contrast.

For each first-difference outcome, the estimator learns three nuisance pieces often written in code-oriented shorthand as mu0(X), mu1(X), and pi(X):

  • \(\mu_0(X)\), the conditional mean of the change score among units with \(G = 0\);
  • \(\mu_1(X)\), the conditional mean of the change score among units with \(G = 1\);
  • \(\pi(X)\), the propensity score for the binary baseline factor.

The learner argument chooses how these nuisance functions are fit. The K argument controls the number of cross-fitting folds, and S controls the number of repeated random splits whose estimates are aggregated. The example below uses learner = "grf" so the binary-DML section mirrors a modern machine-learning AIPW workflow: cross-fitted outcome regressions and propensity scores, estimated with generalized random forests, enter an orthogonal score. The small split settings keep the tutorial render manageable.

set.seed(20260601)
fdid_results_dml_binary <- fdid(
  s = prepared_d,
  tr_period = tr_period,
  ref_period = ref_period,
  method = "dml_binary",
  learner = "grf",
  K = 3,
  S = 1,
  vartype = "robust",
  dml_inference = "score"
)
summary(fdid_results_dml_binary)

2.4 Inference

Use vartype to choose how standard errors are computed:

  • "robust": Heteroskedasticity-robust SE; becomes robust SE clustered at higher level if the user specified cluster_label in fdid_prepare().

  • "bootstrap": Bias-corrected bootstrap confidence intervals. CIs are computed as \((\hat{\tau} - (q_{97.5} - \bar{\tau}^*),\; \hat{\tau} + (\bar{\tau}^* - q_{2.5}))\), where \(\bar{\tau}^*\) is the bootstrap mean and \(q_{2.5}, q_{97.5}\) are bootstrap quantiles. Parallel bootstrap uses doFuture with L'Ecuyer-CMRG streams for reproducible results.

  • "jackknife": Leave-one-out jackknife standard errors.

Default is "robust".

Note: Because the program operates on the wide form, these methods are analogous to cluster robust errors, cluster bootstrap, and cluster jackknife.

2.5.3 missing_data

missing_data controls how missing outcomes are handled:

  • "listwise": Drop a unit if any required outcome is missing (more conservative).

## FDID: A quick review

`fdid()` performs factorial difference-in-differences (FDID) estimation using cross-sectional estimation methods based on **first differences**. It converts the $(Y_{i,t}, G_i, X_i)$ into a cross-sectional form $(\Delta Y_i, G_i, X_i)$ by comparing each period (or average of a time window) to a reference period.

`fdid()` reports both aggregate and dynamic estimates with different definition of $Y_{i,*}$ in $\Delta Y_i=Y_{i,*}-Y_{i,\text{ref}}$:

- Aggregate estimates:
    -   Pre-event average effect for all pre-event periods excluding the reference period: $Y_{i,*}=\bar Y_{i,\text{pre}}$ where $\bar Y_{i,\text{pre}}$ is the average of $Y_{i,t}$ across all pre-event periods except the reference period.
    -   Event-period average effect for all event periods: $Y_{i,*}=\bar Y_{i,\text{event}}$ where $\bar Y_{i,\text{event}}$ is the average of $Y_{i,t}$ across all event periods.
    -   Post-event average effect for all post-event periods: $Y_{i,*}=\bar Y_{i,\text{post}}$ where $\bar Y_{i,\text{post}}$ is the average of $Y_{i,t}$ across all post-event periods.
- Dynamic Estimates:
    -   Dynamic period-by-period estimates relative to the reference: $Y_{i,*}=Y_{i,t}$ for all $t$.

::: {.callout-note appearance="simple"}
**How periods are defined**: `tr_period` defines the event window. Every period before it is “pre”, every period after it is “post”. The reference period is separately set by `ref_period` and does not have to be the last pre-event period. If it's set in event or post-event window, the corresponding window average effect will also exclude the reference period when calculating the average.
:::

::: {.callout-note appearance="simple"}
**Carryout effect**: Because we cannot rule out carryover effects, all periods during or after the event should be considered treated or exposed. Therefore, setting a post-event period as the reference period is not recommended, even though we report separate estimates for the event and post-event periods.
:::

Compared with the TWFE model, our approach

-   forces each period-by-period estimation to use a balanced two-period comparison;
-   makes it easy to plug in selection-on-observables tools (stratification, balancing, matching, IPW, AIPW, outcome modeling, double machine learning, etc.).

::: {.callout-note appearance="simple"}
The reason why OLS is problematic here is the same as the issue with running a two-way fixed effects (TWFE) model using long-format data such as the violation of the no anticipation assumption.
:::


## Estimation

Use `method` to choose an estimator:

| Method | $G$ type | Main estimand |
|---|---|---|
| `"did"` | binary or continuous | no-covariate DID slope/contrast |
| `"ols1"` | binary or continuous | OLS with additive covariate adjustment |
| `"ols2"` | binary or continuous | OLS with $G \times X$ interactions |
| `"ebal"` | binary | entropy-balanced contrast |
| `"ipw"` | binary | IPW contrast via generalized random forests |
| `"aipw"` | binary | AIPW contrast via generalized random forests |
| `"kernel"` | continuous | local-linear level and derivative curves |
| `"dml_plr"` | continuous | scalar partially linear DML slope |
| `"dml_flex"` | continuous | flexible DML level curve $\theta(g)$ and derivative curve $\theta'(g)$ |
| `"dml_incremental"` | continuous | scalar observed-population average derivative |
| `"dml_binary"` | binary | cross-fitted binary-G DML contrast |

Default is `ols1`.

For fitted continuous-$G$ curve objects, use `fdid_contrast()` to report
level comparisons such as $\theta(g_1)-\theta(g_0)$ and `fdid_derivative()` to
report fixed-$g$ derivative values such as $\theta'(g_0)$.

The DML methods use `learner = "linear"` by default for lightweight,
reproducible runs. The rendered DML examples in this tutorial use
`learner = "grf"` to show the flexible nuisance-learning path more clearly.
Other optional learners include `learner = "glmnet"`/`"lasso"`, `"ridge"`,
`"elasticnet"`, `"ranger"`/`"rf"`, `"gam"`, `"nnet"`, and
`"xgboost"`/`"boosting"` when the corresponding backend package is installed.

### Difference-in-Differences

By setting `method = 'did'`, the estimated model is the no-covariate specification:
$$
\Delta Y_i=\beta_0+\beta_G G_i+\varepsilon_i
$$
Here, $\beta_G$ is a cross-sectional analogue of the canonical $2\times2$ DID estimand.

```{r did}
fdid_results_did <- fdid(
  s = prepared_d,
  tr_period = tr_period,
  ref_period = ref_period,
  method = "did",
  vartype = "robust"
)
```

`summary()` reports the point estimates, standard errors and 95% confidence intervals for aggregate estimates and dynamic estimates:
```{r did_sum}

```

### OLS with interactions

By setting `method = "ols2"`, the estimated model corresponds to the $OLS_*$ specification:
$$
\Delta Y_i=\beta_0+\beta_GG_i+\beta_X'\mathbf{X}_i+\beta'_{GX}G_i\mathbf{X}_i+\varepsilon_i
$$

`fdid()` automatically centers covariates before estimation. With centered $X_i$, the coefficient on $G_i$ can be interpreted as consistent estimator for marginal estimand $\tau_{\text{DID-X}}$ discussed in @xu2026factorial. The standard error for `ols2` with `target.pop = "all"` (the default) includes the Lin (2013) super-population correction $\hat{\gamma}'\hat{\Sigma}_X\hat{\gamma}/n$, where $\hat{\gamma}$ are the estimated interaction coefficients and $\hat{\Sigma}_X$ is the sample covariance of the covariates.

### DML binary

`method = "dml_binary"` keeps the binary-$G$ target but replaces hand-specified
outcome and propensity models with cross-fitted nuisance learning. It is best
read as the DML version of an AIPW-style binary contrast.

For each first-difference outcome, the estimator learns three nuisance pieces
often written in code-oriented shorthand as `mu0(X)`, `mu1(X)`, and `pi(X)`:

- $\mu_0(X)$, the conditional mean of the change score among units with
  $G = 0$;
- $\mu_1(X)$, the conditional mean of the change score among units with
  $G = 1$;
- $\pi(X)$, the propensity score for the binary baseline factor.

The `learner` argument chooses how these nuisance functions are fit. The
`K` argument controls the number of cross-fitting folds, and `S` controls the
number of repeated random splits whose estimates are aggregated. The example
below uses `learner = "grf"` so the binary-DML section mirrors a modern
machine-learning AIPW workflow: cross-fitted outcome regressions and propensity
scores, estimated with generalized random forests, enter an orthogonal score.
The small split settings keep the tutorial render manageable.

## Inference

Use `vartype` to choose how standard errors are computed:

-   `"robust"`: Heteroskedasticity-robust SE; becomes robust SE clustered at higher level if the user specified `cluster_label` in `fdid_prepare()`.

-   `"bootstrap"`: Bias-corrected bootstrap confidence intervals. CIs are computed as $(\hat{\tau} - (q_{97.5} - \bar{\tau}^*),\; \hat{\tau} + (\bar{\tau}^* - q_{2.5}))$, where $\bar{\tau}^*$ is the bootstrap mean and $q_{2.5}, q_{97.5}$ are bootstrap quantiles. Parallel bootstrap uses `doFuture` with `L'Ecuyer-CMRG` streams for reproducible results.

-   `"jackknife"`: Leave-one-out jackknife standard errors.

Default is `"robust"`.

::: {.callout-note appearance="simple"}
**Note**: Because the program operates on the wide form, these methods are analogous to cluster robust errors, cluster bootstrap, and cluster jackknife.
:::

## Plotting the results

`plot()` provides visualizations for FDID estimation results:

-   `type = "raw"`: Raw outcome means by group over time.
-   `type = "dynamic"`: Dynamic estimates relative to the reference period.
-   `type = "overlap"`: Propensity-score overlap.
-   `type = "curve"`: Continuous-$G$ curve for `method = "kernel"` or `method = "dml_flex"`.

For `type = "curve"`, use `curve = "level"` or `curve = "derivative"` to make
the estimand explicit. Kernel and `dml_flex` results support both. The
`dml_incremental` method is scalar and should be inspected with `summary()`.
For `kernel` and `dml_flex`, `eval_g` is the estimation grid: the fitted object
stores curve estimates at those points, and `plot(type = "curve")` displays
them without adding new estimation points.

| Method | `curve = "level"` | `curve = "derivative"` |
|---|---|---|
| `"kernel"` | kernel level curve $\hat\mu(g)$ | kernel derivative curve $\hat\delta(g)$ |
| `"dml_flex"` | DML level curve $\hat\theta(g)$ | DML derivative curve $\hat\theta'(g)$ |

`fdid_list()` lets the user visually compare multiple `fdid()` results in one plot.

### Raw means by group

Use `type = "raw"` to plot the outcome means and the 95% confidence intervals in each period for the $G=0$ and $G=1$ group. This plot is purely descriptive -- it does not depend on the estimation method.

```{r}
plot(fdid_results_ols1, type = "raw")
```

### Dynamic estimates

Use `type = "dynamic"` to plot period-by-period estimates relative to the reference period. These estimates come from separate cross-sectional estimations by year, not a single TWFE event-study regression.

```{r}
plot(fdid_results_ols1, type = "dynamic")
```

### Diagnostic test for overlap

For `method = "ipw"` and `method = "aipw"`, the user can assess the overlap assumption using `type = "overlap"`, which plots the propensity score distributions by group.

```{r}
plot(fdid_results_aipw, type = "overlap")
```


### Comparison of methods

Use `fdid_list()` to collect multiple `fdid()` results and plot them together. The plot shows point estimates and 95% confidence intervals for each method.

```{r}
plot(fdid_list(fdid_results_did, fdid_results_ols1, fdid_results_ols2,
               fdid_results_ebal, fdid_results_ipw, fdid_results_aipw),
     ylim = c(-5, 1))
```
